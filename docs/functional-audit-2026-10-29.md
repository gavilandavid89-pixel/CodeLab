# CodeLab functional audit — 2026-10-29

## Scope
Audit of the changes in PR #2 on `feature/design-workspace`: visual design projects/canvas, AI capture exports, design-system laboratory, accessibility checker, reusable component library, and CI coverage. This is a source review plus GitHub Actions/Chromium tests; it is **not** a live deployed-site audit. No Render service was changed.

## Verified
- The PR workflow validates syntax, capture unit tests, design-token/contrast/audit unit tests, component catalog tests, Chromium interaction tests, the full visual-design workflow E2E against the real app/server, and API/Groq health. The full workflow test covers create → edit → undo/redo → drag → duplicate/delete → responsive frame presets/mobile overflow → server persistence/reload → recovery of a newer local edit and a pending offline deletion → convert to web → insert a real library component and verify it persists in the server workspace. It also injects HTTP 429 and 413 responses to verify retry and local-only recovery behavior.
- Design and web capture offer 1×/2×/3×/4× resolution and record the selected scale plus exact output pixel dimensions in the JSON context. Design SVG is rasterized directly at the selected output scale (not enlarged after a low-resolution raster pass) with high-quality smoothing. The chained full-system E2E selects maximum 4× design capture and checks the downloaded PNG dimensions against the context. Web capture removes scripts/embedded frames from its isolated capture document and reports that JavaScript is excluded from the screenshot; Chromium verifies its PNG dimensions at the selected scale. Before rendering, web capture now waits up to 6 seconds for web fonts and image decode/load, records asset readiness in the context JSON, and disables animations/transitions/carets in the cloned capture to reduce inconsistent frames. It also sets a 10-second image timeout. Both flows reject exports above 32 million pixels with a recoverable message rather than attempting an excessive canvas allocation.
- Design-system utilities calculate contrast, generate palettes/tokens, export CSS/JSON, keep a local backup, and synchronize settings through a workspace-authorized server endpoint; the browser test now covers migration, remote save, and import sync. The HTML audit remains static.
- Component library has 8 catalog entries, search/category filtering, sandboxed preview, HTML copy/download, and insertion into the active web project. Its focused browser test uses mocked editor APIs; the full-app E2E now additionally checks real insertion and server persistence.
- Visual design projects are distinguished by `type: "design"`; web project integrations explicitly reject design projects where appropriate.

## Fixes applied during this audit
- **CSS background readiness:** web capture now discovers unique `background-image: url(...)` resources from computed styles, waits for those resources within the same bounded timeout as HTML images/fonts, and reports loaded/failed/pending background counts in the context JSON. The browser capture test includes a data-URL CSS background and checks readiness diagnostics. Remote or broken background assets remain bounded by the timeout and are reported rather than blocking capture indefinitely.
- **Capture sharpness/resolution:** web-capture context now records `pixelWidth`/`pixelHeight` in addition to CSS viewport and scale; capture waits for fonts and image decoding before rasterizing, records loaded/failed/pending image counts, and suppresses animation/transition/caret artifacts in the cloned render. Browser tests assert exact 3× PNG dimensions, successful image readiness, and bounded timeout diagnostics for a stalled image; unit tests assert exact 4× dimensions. Resolution scaling increases raster pixel count, but it cannot restore detail absent from source images or CSS assets.
- Layer selection and property values now use HTML-attribute escaping; layer selection uses data attributes rather than interpolating project IDs into inline JavaScript handlers.
- Text alignment property changes update the canvas immediately.
- Palette swatches are labelled as selecting/using a shade rather than claiming to copy it.
- Uncommitted design-system edits remain in the modal draft when it is closed and reopened during the same page session.
- CSS token insertion deduplicates repeated managed marker blocks.
- Design button layers support safe HTTP(S) destinations. Alt-click tests navigation in a new tab from the editor; HTML export and design-to-web conversion preserve the link with `target="_blank"` and `rel="noopener noreferrer"`. Unsafe schemes such as `javascript:` are rejected and covered by the chained E2E.
- The design-to-web conversion now preserves embedded image layers, ellipse geometry, safe button links, and viewport scaling instead of degrading images/shapes to plain text. The chained E2E verifies the converted page retains the image data URI, ellipse styling, viewport metadata, and resize listener.
- Visual design exports are available as standalone HTML, SVG, and editable project JSON. Exported HTML scales the fixed design frame to the viewport and recalculates on resize; color values are restricted to safe CSS color syntax. The chained E2E downloads all three formats and verifies the HTML responsive behavior and export payloads.
- Canvas keyboard controls include undo/redo, duplicate, delete, and arrow-key nudging by 1 px or 10 px with Shift. Repeated arrow movement groups history snapshots until keyup; the chained E2E verifies movement and duplicate/delete shortcuts without disrupting later toolbar operations.
- Canvas Auto Layout supports row-with-wrap and column flows, configurable 0–200 px spacing and padding, and computes stable positions from insertion order. Computed positions and height feed canvas rendering, AI PNG/SVG capture and context JSON; HTML export and design-to-web conversion emit a responsive flex flow with the chosen direction/gap/padding and stack vertically on narrow screens. Manual dragging/alignment is disabled in Auto Layout to avoid conflicting position models; switch to Free mode for absolute coordinates. The chained E2E verifies column spacing, padding and context metadata.
- Canvas grid spacing is configurable (4/8/16/32 px), independent of grid visibility; optional snap-to-grid rounds dragged layer coordinates on release. Selected layers expose a touch-friendly corner handle for direct resizing, with arrow-key size adjustments and 1 px/10 px increments. Shift-click multi-selection works in the canvas and layer list; selected layers can be aligned to shared edges/centers, distributed evenly horizontally or vertically, and deleted together. The chained E2E verifies grid alignment, direct width/height changes, equal horizontal gaps, and shared top-edge alignment.
- Visual design supports image layers with local PNG/JPEG/WebP/GIF uploads capped at 2 MiB, HTTP(S) image URLs without embedded credentials, editable alt text and object-fit controls. Unsafe protocols and SVG data URLs are rejected. Image layers render in the canvas, SVG/HTML exports and AI capture; context JSON reports image metadata without duplicating embedded base64. The chained E2E uploads a real PNG fixture and verifies image rendering, alt text and all export formats.
- Visual starter templates include landing, dashboard, and portfolio layouts with frame-aware sizing. Replacing a non-empty design requires confirmation, and the previous design (including background) is undoable. The chained E2E applies a dashboard template, verifies all generated layers, and undoes it back to the original image-and-text design.
- Selected layers can be moved backward/forward in the stacking order; the canvas DOM order changes accordingly and the controls disable at the ends. The chained E2E verifies both directions on an image layer.
- Ellipse/circle shapes are supported as first-class design layers, with oval geometry preserved in SVG and responsive HTML. Unit capture tests and the chained E2E verify the exported shape geometry.
- UI wording now explains that token insertion adds CSS variables and does not automatically rewrite every existing color/style.
- Capture sanitization neutralizes quoted and unquoted javascript: URLs in link, image, and form-action attributes.
- Server request handling now tolerates malformed cookie encoding and returns a proper 413 for oversized bodies; rate-limit maps expire stale AI entries and forwarded-IP parsing supports an explicit trusted-proxy hop count.
- Workspace recovery merges local/server projects by ID and update time, preserves pending deletions as per-workspace tombstones, keeps pending imports per account, and avoids false timestamp bumps on page unload.
- A workspace-scoped design-system endpoint persists visual settings; localStorage remains the fallback and old local settings migrate on first use. Design-system writes are serialized to prevent a slow earlier save from overwriting a newer value, and a stale workspace read cannot replace a local save made while it was in flight.
- Forwarded-IP rate limiting preserves proxy-hop positions and rejects malformed chains instead of filtering invalid entries and accidentally shifting the trusted-hop selection; integration coverage uses a two-hop trust configuration.
- Outbound HTTPS calls to OAuth and AI providers now have a configurable inactivity timeout (default 60 seconds, bounded to 1–300 seconds), preventing stalled upstreams from holding requests indefinitely.
- OAuth callbacks now require the signed state to match an HttpOnly, SameSite=Lax, short-lived cookie set when that browser starts login; integration tests verify copied state URLs without the initiating browser cookie are rejected for GitHub and Google.
- Copilot provider settings and user-supplied API keys are now stored under account-specific browser storage keys; account identity resolves before loading AI settings, legacy global keys are discarded when a real account is active, and logout reloads anonymous settings to avoid leaving the prior account's key in memory. A source-level regression guard runs in CI.
- Logout now attempts to flush the current account workspace, preserves unsynced projects in that account's pending-import slot if the save fails, clears the browser's workspace bearer token/ID and local project snapshot, and creates a fresh anonymous workspace. This closes the previous behavior where a cached HMAC workspace token could still authorize requests after the session cookie was cleared. Workspace switching also preserves an already-saved per-account pending snapshot instead of replacing it with the anonymous workspace's local snapshot.
- Design-system local settings are now namespaced by OAuth workspace; legacy browser-wide settings are not imported into a real account, and the design-tools sync listener refreshes when logout switches to an anonymous workspace.
- Design-system sync now checks that the initiating workspace is still active before applying delayed GET responses or queued writes, preventing an in-flight request from a previous account from changing the current account's UI state after logout/switching.
- The user-configurable AI provider URL is validated as HTTPS and resolved against public IP ranges; loopback/private targets are rejected, the resolved address is pinned for the connection, and the server integration test covers a loopback SSRF attempt.

## Follow-up resilience pass — 2026-10-29

- **Session lifecycle:** session identifiers are restricted to the generated 48-character hex format before filesystem access/deletion; session records must have a valid expiry and provider identity. Session writes use private temporary files and atomic rename. Expired sessions are cleaned at startup and by a rotating cleanup that processes at most 200 JSON session files per pass, without letting unrelated temp files block the scan. Whitespace-only secret configuration is treated as unset. Generated workspace secrets are written to a private temporary file and atomically published without overwriting another instance's key; permissions and stability across restart are tested. Session cleanup coverage seeds 201 expired records to verify bounded batches eventually reach records beyond the first 200.
- **Workspace integrity:** anonymous initialization cannot squat on the deterministic GitHub/Google workspace-ID namespace. Malformed persisted workspace JSON/shape returns a controlled corruption error rather than silently becoming an empty workspace. Project IDs and design-layer IDs must be unique; malformed design containers and designs over 500 layers are rejected before persistence. The editor blocks adding layers above that cap, normalizes array-valued legacy design metadata, and AI capture fails cleanly for oversized designs.
- **Static file boundary:** lexical traversal checks are supplemented by realpath containment checks, so a symlink inside public/ cannot expose private files such as server.js. Regression coverage exercises both encoded traversal and a temporary symlink to a private file.
- **Provider requests:** upstream response bodies are capped at 5 MiB and aborted/error streams settle once; AI provider resolution rejects private/reserved IP ranges, pins a validated address, and prefers IPv4 when a public IPv4 record is available. AI token/rate-limit and workspace body/project limit environment values are clamped to safe integer ranges.
- **Credential isolation:** a user-provided AI key is paired with that user's chosen provider endpoint; it no longer accidentally sends the configured server key to a client-selected URL. The response's via metadata reflects the credential source actually used.
- **Sync recovery and preview isolation:** a workspace payload-validation HTTP 400 is shown as a sync-validation warning without permanently marking the server offline; the next valid save can recover. Preview console messages are accepted only from the app's own opaque-origin sandboxed iframe, and console messaging continues to work with the sandbox's null origin.
- **Additional regression coverage:** CI checks invalid server limit configuration, secret file permissions/stability across restart, malformed and duplicate project/layer identities, excessive layer counts, private IPv6 provider targets, symlink escape prevention, preview message isolation, and 400 validation recovery. The full chained E2E and all workflow steps passed on commit 09349d95d8f998ac4d1a857e98e0e5baed630cf3.
## Remaining limitations / coverage gaps
- The focused browser tests for the design-tools and component-library dialogs extract their modal markup and mock editor APIs. Design-system workspace sync is tested with a simulated API, and server persistence/auth is covered by an integration test; live OAuth cross-device behavior still requires a deployed environment.
- The chained full-system E2E now follows one real browser session against one real local server through design creation/editing, undo/redo, drag, direct canvas resize, duplication/deletion, responsive frame presets, AI capture artifacts (valid PNG or documented SVG fallback plus context JSON), HTML/SVG/project-JSON export through the real export menu, reload/offline recovery, conversion to web, design-system save/export/reload against the workspace API, component insertion, and injected HTTP 429/413 recovery. This is an integrated regression journey; focused unit/browser tests remain complementary, not substitutes for it.
- AI web screenshot capture depends on loading html2canvas from its external script source. The script load now has a bounded 12-second timeout (shorter values can be injected in tests); if it errors or stalls, the feature falls back to exporting JSON context without PNG. Font/image readiness waits are bounded to 6 seconds so broken or remote assets cannot hang capture indefinitely; the JSON records readiness, including pending image counts, to make missing assets diagnosable.
- Design-token JSON import validates all required colors and enforces the supported typography, spacing, and radius ranges before applying anything, preventing malformed files from being silently normalized into a different design system. Browser tests cover invalid colors and out-of-range numbers; the full-system journey verifies export → edit → import → server persistence → reload recovery. Design-token settings now synchronize per workspace with localStorage retained as a fallback. Remote design-system GET/PUT requests retry up to three times for network failures, HTTP 429, and HTTP 5xx with bounded backoff; non-retryable client errors fail immediately. The focused browser test injects a 429 and verifies that a subsequent PUT persists settings remotely. The full-system E2E independently validates the complete save → server persistence → JSON export → reload → settings recovery journey. Live cross-device behavior still requires a deployed OAuth-enabled environment to validate.
- The accessibility audit recognizes descriptive `alt` text as the accessible name of an image-only link and SVG graphics with `role="img"` plus a title. Empty-alt decorative images do not falsely name a link or button. The design-tools and component-library dialogs keep keyboard Tab/Shift+Tab navigation inside the open modal and support Escape-to-close. The component library clears stale selection/source and disables copy, export, and insertion actions when a search has no matches. It remains static regex-based HTML analysis: it does not execute JavaScript, inspect dynamic states, compute CSS contrast, or replace a full accessibility evaluation.
- Monaco editor loading is asynchronous; initialization now uses a generation guard so stale callbacks from a previous project are ignored. The full-app E2E waits for the active project's editor contents before exercising insertion.
- Workspace sync schedules automatic retries after HTTP 429 with backoff delays of 2 s, 5 s, then a 15 s cap. HTTP 413 is distinguished from a connectivity outage; local changes are retained and a later successful smaller save clears the warning. The E2E checks mobile viewport dimensions, canvas frame sizing, and document-level horizontal overflow, but it is not yet a screenshot-based visual regression test across multiple device sizes.
